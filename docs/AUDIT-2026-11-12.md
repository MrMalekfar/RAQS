# RAQS audit and remediation plan

Date 2026-11-12. Original code base `521c032`, branch `codex/profile-schema-migration`.

This is a historical audit record. Later sections record remediation and follow-up acceptance. Current cross-platform review results are in the [test guide](../tests/README.md#verified-review-branches-2026-11-19).

RAQS calculates Rydberg-receiver response from field configuration and Lindblad evolution through IF extraction and AoA estimation. CLI, multipoint studies and the Qt workbench consume this core. The audit assumed local single-user research, multiple computational processes and Monte Carlo repetition. Public multiuser hosting was outside the product workload.

The initial audit identified three storage/validation findings requiring correction and three initialization/reproducibility findings. It changed no executable code, baseline, seed or tolerance. Physical safeguards and targeted tests were present. Compatibility of every configuration combination remained unverified.

## Required fixes

### 1. A new report can remain alongside an earlier run's arrays — P1

The original locations were `cli.py:275`, `main`, and `simulation/profile_execution.py:353`, `save_profile_results`. CLI wrote `run_report.json` before exporting arrays, and README allowed reusing an output directory.

Injecting `OSError` at the save boundary left a new report with old arrays. A diagnostics run in an earlier sensing directory also retained old sensing arrays. The reproduction verified storage behavior using synthetic execution, without claiming physical validity.

The smallest complete fix requires a fresh single-profile destination and rejection of conflicting output before computation. If replacement is required, publish a fully validated temporary run only after completion. Publish the completion marker last. Reordering two writes alone leaves partial-publication cases.

Acceptance requires NPZ/report failures and diagnostics on an old path to preserve the previous successful run and prevent mixed artifacts. CLI, studies and readers need a clear completion contract. Delaying this fix risks attributing an earlier run's arrays to a newer report.

### 2. IF-only export fails on valid spectrum metadata — P1

The original consumer was `simulation/if_only.py:117`, `save_if_only_arrays`, with `run_profile_spectrum` producing the spectrum. IF-only arrays must remain numerical and loadable without objects/pickle.

The exporter excluded only `analytical_contract`. String `steady_state_backend` and dictionary `radiative_model` entered the array list and failed numerical validation. Both cases reproduced independently. The same output without metadata exported successfully. The parser accepted IF-only with an explicit backend and the relax002 radiative model.

Define a shared explicit numerical-spectrum-key contract for AoA and IF-only, retaining metadata in report JSON. Preserve numerical validation. Acceptance requires `allow_pickle=False` loading with direct/QuTiP backends and radiative enabled. The original `tests/test_noise013_if_only.py:157` export case missed these combinations. Delaying the fix can discard an expensive valid calculation at its final storage step and compound finding 1.

### 3. Model API silently drops dissipation for invalid rates — P1 for direct callers

The original locations were `physics/hamiltonian/create_sensor_model.py:155`, `:181`, `:194`. `create_sensor_model` is also exported from `physics/__init__.py`.

The constructor converts decay, dephasing and transit rates to collapse operators. Its unvalidated `rate > 0` condition skipped negative and NaN channels. Separate calls with negative decay, NaN dephasing and negative transit returned an empty dissipation list without an error. Density positivity cannot detect that unintended physical-model change.

The public parser rejects many such inputs earlier. This finding covers direct API consumers and callers without prior validation. Validate vector length/type and finite nonnegative rates at the function boundary, retaining valid zero. Keep `PreparedRadiativeGraph` and None semantics explicit. Measure validation cost in hot solver paths. Reject invalid channels without correction.

Acceptance covers negative, boolean, nonfinite and wrong-length inputs while preserving valid Hamiltonian/Liouvillian results. Check callers in steady/temporal paths and parity, trace, Hermiticity and positivity tests. Delaying correction allows plausible numerical results for unintended physics.

## Follow-up fixes

### 4. Internal imports still construct ARC and calculate density — P2

Original locations were `config/parameters.py:160`, `config/atomic_config.py:33`, also reachable from `physics/__init__.py` and `arc/interface.py`.

Module-level `CALCULATED_N0 = calculate_atomic_density_with_arc()` ran during import. Importing the Hamiltonian constructor with otherwise explicit inputs failed on a read-only ARC database before calling it. Test collection failed through the same path. Guarding resolved-level publication alone left other import side effects.

Move ARC construction and density publication into explicit initialization. Readers before initialization must fail clearly. Review snapshot/rollback and consumers of `CALCULATED_N0` and `SI_Constants.N0`. Acceptance requires imports without atom construction/file writes and preserved failure for explicit initialization against broken ARC. The independent `--help` route already passed. Delaying the fix ties static analysis and atom-independent tests to user ARC-directory state.

### 5. Regression tests still demand an invalid historical reference — P2

Original locations were `tests/test_physics_baseline_regression.py:19` and `tests/test_parameter_injection_rf002.py:35`, with incompatibilities documented in `post_physics_baseline.json:65`.

The post-physics file labels Phase 0 as physically invalid and lists changed cell length, Rabi, transit and units. Tests nevertheless demanded current-default agreement with Phase 0. An example is `od_factor=402643.6365` for the old cell length versus `301982.7274` for 75 mm. A permitted QN-001A skip leaves that conceptual mismatch unresolved.

Preserve historical files and distinguish historical compatibility from current-model regression. Build an independent current fixture with explicit prepared channel, provenance, code/ARC version, units and SHA-256. Independently review post-physics values before selecting a replacement reference. Acceptance requires actual explicit-channel execution and honest skip reporting. Preserve baseline/tolerance/seed contracts. Delaying this fix leaves current physics weakly protected and may demand a return to old physics after QN resolution.

### 6. Single-profile CLI runs lack sufficient reproducibility receipts — P2

Original location `cli.py:270` onward was compared with `raqs_gui/worker.py:68` onward. CLI saved arrays/reports without a full consumed-input snapshot, artifact hashes, commit or major-library versions equivalent to GUI. Physical fields and ARC version alone cannot identify the producing code/input after edits. `InputProvenance` labels scientific origin.

Reuse the existing receipt contract for CLI with the consumed snapshot, hashes, commit/dirty state and major dependency versions, coordinated with finding 1. Acceptance requires retained producing input/version after edits, detection of output tampering and explicit null fields when Git is unavailable. Delay leaves research provenance dependent on memory or external records.
